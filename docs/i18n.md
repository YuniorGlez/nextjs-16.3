# i18n multiidioma

El núcleo soporta `es`, `es-ES`, `en`, `en-GB`, `fr` y `pt` sin dependencia externa.

## Configuración por cliente

La migración `0007_i18n` añade `settings.i18n` (sin seed ni DDL ejecutado por este cambio):

```json
{"defaultLocale":"es","enabledLocales":["es","en"]}
```

El panel `/admin/idiomas` permite cambiar ambos campos y exige la capacidad RBAC `i18n.manage`.
La validación rechaza idiomas fuera del catálogo, duplicados, un default no habilitado y más de 12
idiomas. Para habilitar un idioma nuevo hay que añadirlo a `SUPPORTED_LOCALES`, sus tests y esta
documentación; no se generan traducciones automáticamente.

## URLs y contenido

Las URLs existentes (`/` y `/<slug>`) se conservan como fallback del idioma por defecto. Las
alternativas se publican como `/<locale>/...`; `proxy.ts` solo reescribe rutas públicas localizadas
hacia las rutas actuales, y excluye `/admin`, `/api`, `/preview` y ficheros. No se usa el locale para
autenticación o autorización.

`pages.translations` es un JSONB aditivo con forma `{ "en": { "name", "seo", "content" } }`. Solo se
aplican claves que ya existen en el contenido base, campo a campo. El resolver limita textos,
elimina etiquetas HTML y hace fallback determinista al valor original; nunca sobrescribe el estado
publicado ni inventa traducciones.

La metadata de páginas genera `canonical` y `hreflang` por idioma habilitado. El sitemap incluye
cada URL localizada y solo consulta páginas publicadas; previews mantienen `noindex`.

El selector público es HTML accesible con enlaces normales, por lo que funciona sin JavaScript.

## Migración

Revisar primero `bun run db:migrate:status` y aplicar en el entorno correspondiente con `bun run db:migrate`.
Esta entrega no ejecuta DDL ni seed.

## Seguridad

Los locales se validan contra un catálogo cerrado en servidor. Nunca usar un locale recibido del
cliente para decidir permisos, sesiones o acceso a APIs.
## Comprobación rápida

`bun run test`, `bun run typecheck`, `bun run lint`, `bun run build` y `git diff --check`.

## Añadir idioma

1. Añadir el código BCP-47 al catálogo cerrado y ajustar los tests.
2. Documentar la etiqueta y habilitarlo desde `/admin/idiomas`.
3. Cargar traducciones explícitas en `pages.translations`; no traducir automáticamente contenido del cliente.
4. Verificar canonical, alternates, sitemap y fallback.
